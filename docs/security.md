# Security Model

## Custody

Non-custodial end to end. Users sign every payment in their own wallet; the platform never asks for user keys and never holds user deposits. Session-wallet secrets generated by the liquidity engine are AES-256-GCM encrypted at rest and zeroized from memory after use; they are never returned to clients.

## Session access

Status and restore endpoints bind responses to the paying wallet via token + Ed25519 signature verification. Cross-session reads are rejected.

## Payment integrity

- Server-side price resolution; HMAC-signed quotes with 10-minute expiry
- Durable signature replay protection across every payment flow
- On-chain verification of recipients and amounts before activation

## Edge protection

- Cloudflare ASN filtering for datacenter scanner traffic (verified bots allowed)
- Cloudflare rate limiting on public endpoints
- Cloudflare Turnstile (invisible) on lead-capture endpoints
- Server-side input validation on every public endpoint — payload length limits, Solana base58 address validation, injection-marker rejection

## Recovery guarantees

- If a wallet-distribution batch fails mid-way, funded children are swept back to the master wallet — no lamports can be stranded in untracked keypairs.
- Crashed session initializations self-heal on verification retry.
- Refund claims are idempotent — a sweep can only execute once per session.

## Verifiability

All balances, payments, and refunds are auditable on Solscan. The site reports no figures it cannot back on-chain.
